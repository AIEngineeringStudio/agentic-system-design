## Selection rules

1. A numbered request wins over keyword matching.
2. A named design wins over incidental mentions of technologies inside its
   description.
3. An unlisted problem is valid: identify its main architectural concern; load
   the **closest one** of the nine modules. Say that it is a custom case, not
   catalog case #N.
4. When two modules are equally important, read the primary one first. Read one
   additional module only when the user requests that cross-domain depth or a
   missing mechanism makes the current stage impossible.
5. A user asking about the **catalog only** should not trigger module load.
6. A user can request a new module or a full design; do not impose an order or
   an exam.
