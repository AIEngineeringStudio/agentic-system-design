# A problem-driven Agentic AI System Design curriculum

This is not a traditional course organized by technologies.

The learning method should be:

Start with a real-world AI system design problem

```
+--------------------------------------------------------------------------+
|                 START WITH A REAL-WORLD AI PROBLEM                       |
|                                                                          |
|  Design an enterprise assistant that accesses internal systems           |
|  and performs approved actions.                                          |
+--------------------------------------------------------------------------+
                                    |
                                    v
+--------------------------------------------------------------------------+
|                 INTRODUCE CONCEPTS WHEN NEEDED                           |
|                                                                          |
|  Agent loops | Tools | MCP | Authentication | Authorization              |
|  State management | Human approvals                                      |
+--------------------------------------------------------------------------+
                                    |
                                    v
+--------------------------------------------------------------------------+
|                  BUILD THE SIMPLEST WORKING SOLUTION                     |
|                                                                          |
|  Architecture diagram | Code | Request flow | Working behavior           |
+--------------------------------------------------------------------------+
                                    |
                                    v
+--------------------------------------------------------------------------+
|                  EVOLVE INTO PRODUCTION ARCHITECTURE                     |
|                                                                          |
|  Security | Retries | Scalability | Isolation | Observability            |
|  Evaluation | Cost                                                       |
+--------------------------------------------------------------------------+
                                    |
                                    v
+--------------------------------------------------------------------------+
|                  EXTRACT REUSABLE ARCHITECTURE PATTERNS                  |
|                                                                          |
|  Learn when to reuse the design, when to change it, and why.             |
+--------------------------------------------------------------------------+
```

The key is to learn MCP by designing systems that need MCP, learn Generative UI
by building interactive AI products, and learn multi-agent patterns by solving
problems where a single agent is insufficient.

It has a broad catalog, with selected deep-dive designs rather than making every
case equally large.

The catalog includes 16 recommended deep-dive designs, practical build
objectives and production concerns for every problem, plus one worked
architecture example for an expense-analysis MCP App.

It is a learning blueprint, not 73 completed implementations. The detailed
explanations, diagrams and working code will come as we work through each case.

### Where I would start

Problem #1 — Design an AI Support Assistant.

We begin with a basic AI application, identify its weaknesses, introduce
grounding and structured outputs, build the simplest solution, and then extend
it with production requirements. From there, we progress to tool calling, MCP
and increasingly sophisticated architectures.

This keeps the learning tied to practical architectural decisions rather than
memorizing technologies.
